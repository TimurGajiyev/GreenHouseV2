# Калькулятор «Zharkent» — полный обход, 29.10.2026

Журнал второго полного обхода калькулятора коллеги <https://zharkent.tail042aa5.ts.net/>. Кнопки
нажимались по очереди, после каждого нажатия проверялось, что именно изменилось. Скриншоты
лежат в [screens/](screens/), по папкам. Как устроен его метод, разобрано в [README.md](README.md);
восстановленный расчёт — в [recreate.py](recreate.py).

**Что изменилось на его сервере из-за обхода.** Я запустил 4 сценария, у всех имена начинаются с
«Тест (Тимур) — …», и они теперь есть в его истории расчётов. Пятый запуск повторял умолчания;
приложение его не сохранило (раздел 6). Ничего не удалял, галочку *delete* не трогал.

## 4. Раздел «Data» — замеры

Скриншоты: [screens/data/](screens/data/) — вся страница, обе площадки за каждый из 14 месяцев
(`d-k-01…14`, `d-m-01…14`), всплывающие подсказки графиков, 7 «?», таблицы по месяцам, RU.

- **Кнопки месяцев** показывают долю полных часов: например, «Dec 25 · K 0 % · M 89 %».
- **Подсказка столбца месяца** — из скольких часов собрана энергия и откуда. Например, май 2026:
  у Jenbacher Жаркент 2 «410 CSV, 288 myPlant», то есть 288 часов взяты из myPlant, а не из
  собственного CSV.
- **Подсказка часа** — значение каждого источника. Сеть — средняя за окно myPlant, например
  00:15–01:10, мин. 171, макс. 993 кВт.
- **Подсказка 5-минутного шага** — если не хватает хотя бы одного значения, баланс не замыкается:
  «cannot close: a value is missing».
- **Легенда** скрывает серию ([d-k-legend-import-hidden](screens/data/d-k-legend-import-hidden.png)).

Каждый сценарий: страница загружается заново (значения по умолчанию), меняется **одно** значение,

battery sizes every 5 minutes for Krakhmal, Meshki and both joined… (about half a minute on the
server; one run at a time)»* и кнопка **Stop** сверху ([s1-export-1-running](screens/runs/s1-export-1-running.png)).
После расчёта новая строка появляется в истории и сразу открывается.

Скриншоты: `screens/runs/s1…s5-*` (входные данные, ход расчёта, результат).

**Что видно из сценариев:**

1. **Выдача в сеть ничего не меняет** для всех размеров, которые он показывает. Меняются только
   маленькие СНЭ «вне диапазона»: без выдачи правило там принудительно останавливает ГПУ, с
   выдачей держит её на 50 % и отдаёт излишек. Например, Krakhmal 1 МВт·ч × 0,25 C: экономия −2,6 → 70,3.
2. **Диапазон 80 % на его же модели лучше, чем 90 %.** Экономия чуть выше, пусков на 19 % меньше,
   СНЭ служит дольше (10,6 года против 8,6). Значение 90 % дано как решение «Richard, 14.10.2026»,
   а не как результат расчёта.
3. **Цена сети — самый сильный рычаг.** 60 вместо 50 тг/кВт·ч дают +32 % экономии на Krakhmal
   (119,8 против 90,5), и Meshki начинает окупаться. Так получается потому, что большая часть его
   экономии — замещение импорта.
4. **Заполнение пропусков почти не влияет** на Krakhmal и Meshki (меньше 1 %). Joined сильнее:
   «сейчас» 615,6 против 600,7 (+2,5 %), шагов на 12 % меньше.
5. **«Лучший размер» неустойчив.** На Krakhmal 2 МВт·ч × 0,5 C (2,45 года) и 1 МВт·ч × 1 C
   (2,46 года) почти равны, поэтому любое небольшое изменение (диапазон, цена, пропуски) меняет
   победителя на 1 МВт·ч × 1 C. А тот изнашивается за 3–5 лет.
6. **Одинаковые входные данные не считаются заново.** S5 отличался от умолчаний только именем.
   Через ≈ 30 с строка не добавилась, открылся расчёт «Default inputs» от 16.10, новое имя
   пропало, никакого сообщения не было. Скорее всего, расчёт узнаётся по отпечатку входных
   данных (скрытый столбец *fp*). Это не ошибка, но поведение стоит подписать на странице.
